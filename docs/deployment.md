# Free personal deployment (€0/month)

| Part | Where | Cost |
| --- | --- | --- |
| API (Docker, .NET 10) | Render free web service | €0 |
| Dashboard | Render free static site | €0 |
| Database | Neon free PostgreSQL (persistent) | €0 |
| AI | Gemini API free tier | €0 within quota |
| Sign-in | Google sign-in, restricted to your email | €0 |
| DBot | Loaded unpacked in Chrome (Developer mode) | €0 |

**Trade-offs:** the free API sleeps after about 15 minutes idle and takes up to a minute to wake. Free-tier limits and policies can change. Google may use content sent to the Gemini free tier to improve its products. Contact details are never sent to Gemini.

## How access is protected

- Every API endpoint, apart from `/api/health`, `/api/auth/config`, `/api/auth/google` and the default CV instructions, needs a JobPilot session.
- You get a session by signing in with Google. The API checks the Google ID token's signature, that it was issued for your client ID, that the email is verified, and that the email is in `Auth__AllowedEmails`. It then issues its own 30-day session token, signed with `Auth__SigningKey`.
- If auth isn't configured, the API only starts when it listens on `localhost`/`127.0.0.1`. That's local development mode, with no sign-in. On any other address it refuses to start.

## 1. Google sign-in (Google Cloud Console, free)

1. Create a project at <https://console.cloud.google.com/>.
2. Open **Google Auth Platform → Branding** and configure the consent screen: an app name and your email. Leave the app in **Testing** mode and add your Google account under **Audience → Test users**.
3. Open **Clients → Create client**, choose application type **Web application**, then fill in:
   - **Authorized JavaScript origins:** `https://<your-dashboard>.onrender.com`. Add `http://localhost:5173` too if you want to test sign-in locally.
   - **Authorized redirect URIs:** `https://<your-extension-id>.chromiumapp.org/`. DBot shows this exact address on its sign-in screen, under "Setting up Google sign-in?".
4. Copy the **Client ID**. You don't need the client secret.

The unpacked extension's ID stays the same as long as you load it from the same folder. If you load it from a different folder, update the redirect URI.

## 2. Neon database (free)

1. Create a project at <https://neon.tech/>.
2. Copy the connection string. It looks like `postgresql://user:password@ep-…neon.tech/neondb?sslmode=require`.
3. Optional: copy your existing local history (profile, jobs, generated CVs) into Neon. From `services/api`, with the local API stopped:

   ```powershell
   dotnet run -- copy-database --to "postgresql://user:password@ep-…neon.tech/neondb?sslmode=require"
   ```

   You can run it again safely: jobs that already exist are skipped, and the profile is overwritten with the local one. Keep `jobpilot.db` as a backup.

## 3. Deploy on Render

1. Push this repository to GitHub, then in Render choose **New → Blueprint** and select it. `render.yaml` creates `jobpilot-api` and `jobpilot-dashboard` on free plans.
2. Fill in the secret values when prompted:

   | Variable | Value |
   | --- | --- |
   | `DATABASE_URL` | Neon connection string |
   | `GEMINI_API_KEY` | Your Gemini API key |
   | `Auth__GoogleClientId` | Client ID from step 1 |
   | `Auth__AllowedEmails` | Your Google address, e.g. `you@gmail.com` |
   | `DASHBOARD_ORIGIN` | `https://<your-dashboard>.onrender.com` |
   | `VITE_API_BASE_URL` (dashboard) | `https://<your-api>.onrender.com` |

   `Auth__SigningKey` is generated by Render. If you change it, all existing sessions are signed out.
3. After the first deploy, check `https://<your-api>.onrender.com/api/health`. Then open the dashboard and sign in.
4. If the service names Render assigns differ from your guesses, update `DASHBOARD_ORIGIN`, `VITE_API_BASE_URL` and the Google client's origins to match, then redeploy.

## 4. Point DBot at the hosted API

From `apps/dbot-extension`:

```powershell
Copy-Item .env.example .env   # then set VITE_API_BASE_URL=https://<your-api>.onrender.com
npm install
npm run build
```

Reload DBot in `chrome://extensions`, open the side panel and choose **Sign in with Google**. To go back to the local API, remove `VITE_API_BASE_URL` from `.env` and rebuild.

## 5. Check everything before you switch off the local API

- Sign in on the dashboard and in DBot.
- In the dashboard: edit and save your profile, analyse a job, update an application's status.
- In DBot: analyse a job, **Make CV**, **Download PDF**, the profile tab, and **Ask AI**.
- Upload and download a CV attachment.
- Sign out, and confirm that `https://<your-api>.onrender.com/api/jobs` returns 401 in a private window.

## Backups

Neon's free plan keeps a short history for point-in-time restore. For your own copy, use `pg_dump` with the Neon connection string from time to time, or keep the local SQLite file up to date.
